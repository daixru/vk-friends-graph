# Отчёт по практической работе

## Сбор данных VK и анализ центральности вершин графа

**Дисциплина:** «Интеллектуальные системы и технологии».  
**Дата подготовки:** 24 октября 2026 года.

## 1. Цель и постановка задачи

Цель работы - получить данные о дружеских связях пользователей VK, построить граф социальной сети и определить наиболее центральные вершины по трём показателям: посредничеству, близости и собственному вектору.

В рамках проекта исходными данными выбраны профили двух учебных групп, а область сбора расширена до друзей и друзей друзей этих профилей.

Для достижения цели выполнены следующие этапы:

1. Подготовлен список исходных профилей с указанием учебной группы.
2. Короткие имена профилей преобразованы в числовые идентификаторы VK.
3. Получены и сохранены доступные списки друзей.
4. Построен неориентированный граф связей в пределах двух кругов от исходных профилей.
5. Для всех найденных вершин рассчитаны три показателя центральности.
6. Сформированы топ-10 по каждому показателю и проведено сравнение результатов.

## 2. Исходные данные и модель графа

Исходный список содержит **33 профиля**: 17 из первой учебной группы и 16 из второй. Входные данные хранятся в `seeds.csv` в формате `group,profile`. Профиль может быть задан числовым ID, коротким именем или ссылкой на VK.

Социальная сеть представлена простым неориентированным невзвешенным графом:

$$
G=(V,E),
$$

где вершина соответствует профилю VK, а ребро - обнаруженной дружеской связи. Если хотя бы один полученный список подтверждает связь двух выбранных профилей, в граф включается ребро. Повторяющиеся рёбра объединяются; петли, соединяющие вершину с самой собой, исключаются.

Пусть $S$ - множество исходных профилей, а $N(U)$ - объединение друзей профилей множества $U$ по доступным спискам. Тогда:

Первый круг - друзья исходных профилей, кроме самих исходных профилей:

$$
V_1 = N(S) \setminus S
$$

Второй круг - друзья первого круга, не вошедшие в предыдущие множества:

$$
V_2 = N(V_1) \setminus (S \cup V_1)
$$

Все вершины анализируемого графа:

$$
V = S \cup V_1 \cup V_2
$$

Это определение использует **наблюдаемые списки друзей**. Из-за недоступных или ещё не полученных списков фактическая двухшаговая окрестность исходных профилей может быть шире.

## 3. Получение и сохранение данных

### 3.1. Работа с VK API

Для разрешения коротких имён используется метод `users.get`, для получения связей - `friends.get`. В проекте задана версия API `5.199`. Токен передаётся через переменную окружения `VK_TOKEN`, а запрос выполняется при помощи `curl`.

Сбор выполняется в два основных прохода:

1. Получение друзей исходных профилей и формирование первого круга.
2. Получение друзей профилей первого круга и формирование второго круга.

При необходимости параметр `--complete-boundary` включает дополнительный проход по профилям второго круга. Он нужен для обнаружения связей между граничными вершинами, а вершины третьего круга в анализируемую сеть не добавляются. В исследуемом наборе сохранённых списков второго круга нет.

Один запрос `friends.get` запрашивает до 5000 записей. Если возвращённый размер списка больше полученной страницы, следующие страницы загружаются с увеличением `offset`. В кэш попадает только полностью полученный список.

### 3.2. Обработка недоступных данных

Каждый успешно полученный список сразу записывается в `friends_cache.json`, включая пустые списки. При новом запуске такие профили повторно не запрашиваются. Ошибки доступа к отдельным профилям заносятся в `errors.csv`; при глобальных ограничениях API или сетевой ошибке сбор останавливается с сохранением частичного графа.

В текущей реализации используется постоянный интервал между запросами. Предварительная проверка закрытости, автоматические повторы запросов, бэкоф и восстановление состояния сессии отсутствуют. Сохранение уже полученных списков относится к хранению данных и позволяет избежать их повторного получения.

## 4. Методы анализа

Обозначения: $n=|V|$, $m=|E|$, $d(u,v)$ - длина кратчайшего пути, $c_v$ - размер компоненты связности вершины $v$.

### 4.1. Центральность по посредничеству

Посредничество характеризует роль вершины как связующего узла: насколько часто через неё проходят кратчайшие пути между другими вершинами.

Для неориентированного графа используется нормированное значение:

$$
C_B(v)=\frac{2}{(n-1)(n-2)}
\sum_{\substack{s<t\\s,t\ne v}}
\frac{\sigma_{st}(v)}{\sigma_{st}},
$$

где $\sigma_{st}$ - количество кратчайших путей между $s$ и $t$, а $\sigma_{st}(v)$ - число таких путей, проходящих через $v$ как промежуточную вершину. Пары без пути не вносят вклад. Для графа менее чем из трёх вершин показатель принимается равным нулю.

Для большого графа применяется выборка источников. Из всех вершин равномерно без возвращения выбираются $k$ источников. От каждого из них выполняется обход кратчайших путей по всему графу. Полученные вклады агрегируются и масштабируются с коэффициентом $n/k$, чтобы оценить результат полного расчёта.

Выборка ограничивает число **источников обхода**, а не множество оцениваемых вершин: показатель рассчитывается для всех найденных профилей. При фиксированном `random_seed` состав выборки воспроизводится.

### 4.2. Центральность по близости

Близость показывает, насколько короткие пути соединяют вершину с другими вершинами. В реализации используется обратное среднее расстояние внутри компоненты с поправкой Wasserman-Faust:

$$
C_C(v)=\frac{c_v-1}{n-1}
\cdot\frac{c_v-1}{\sum_{u\in C(v),\,u\ne v}d(v,u)}.
$$

Для связного графа поправка равна единице. Для изолированной вершины показатель принимается равным нулю. В учебной презентации также приведена ненормированная форма $1/\sum d(v,u)$; в связном графе она отличается от используемой нормированной формы постоянным множителем $n-1$ и даёт тот же порядок вершин. Гармоническая центральность $\sum 1/d(v,u)$ в проекте не используется.

При выборочном расчёте в каждой компоненте выбирается множество опорных вершин $P$. Расстояния от этих вершин используются для оценки среднего расстояния до каждой вершины:

$$
\widehat C_C(v)=\frac{c_v-1}{n-1}
\cdot\frac{|P\setminus\{v\}|}
{\sum_{p\in P\setminus\{v\}}d(p,v)}.
$$

В неориентированном графе расстояния симметричны, поэтому обход от одной опорной вершины даёт расстояния до неё для всех остальных вершин. Если выбранная вершина сама входит в $P$, нулевое расстояние до себя исключается из среднего. Когда размер компоненты не превышает размер выборки, близость рассчитывается точно.

### 4.3. Центральность по собственному вектору

Этот показатель учитывает важность соседей: связь с центральной вершиной вносит больший вклад, чем связь с периферийной.

Пусть $A$ - матрица смежности графа. Центральности определяются компонентами собственного вектора, соответствующего наибольшему собственному значению:

$$
Ax=\lambda_{\max}x,\qquad
x_v=\frac{1}{\lambda_{\max}}\sum_{u:\{u,v\}\in E}x_u.
$$

Расчёт выполняется численным решателем igraph **без выборки источников**. Вектор нормируется по евклидовой норме: $\sum_v x_v^2=1$ внутри каждой компоненты связности. В коде для одиночной вершины отдельно принято значение 1. При нескольких компонентах значения, нормированные отдельно, не следует сравнивать между компонентами; в исследуемом графе компонента одна.

### 4.4. Выбор вычислительного подхода

Расчёты выполняются нативным backend библиотеки igraph; NumPy используется для хранения и обработки числовых массивов. Плотная матрица смежности для всего графа не создаётся.

Для невзвешенного графа полный расчёт посредничества и близости требует обходов от всех вершин. Выборочный вариант сокращает число обходов с $n$ до $k$: ориентировочная трудоёмкость изменяется с $O(n(n+m))$ до $O(k(n+m))$. Это позволяет обработать граф из миллионов вершин, сохранив значения для каждой из них.

Точный режим реализован параметром `--exact`, но в результатах данного отчёта он не использовался. Ошибка выборочных оценок и доверительные интервалы не рассчитывались; для проверки устойчивости рейтинга следует сравнивать несколько размеров выборки и случайных инициализаций.

Более значительное совпадение двух последних топов согласуется с их общей чувствительностью к расположению вершины в центральной части сети; это интерпретация данного результата, а не универсальное правило для любых графов.

## 6. Проверка реализации

Для проекта подготовлен **21 автоматический тест**. Проверяются разрешение идентификаторов и групп, пагинация, сохранение полученных списков, обработка ошибок и прерывания, двухшаговая граница графа, удаление повторных рёбер, расчёт метрик и построение топов.

Для проверки формул используется, в частности, граф-цепочка из трёх вершин $a-b-c$. Его точные нормированные центральности известны:

| Вершина | Посредничество | Близость | Собственный вектор, L2 |
| --- | ---: | ---: | ---: |
| $a$ | 0 | $2/3$ | $1/2$ |
| $b$ | 1 | 1 | $1/\sqrt{2}$ |
| $c$ | 0 | $2/3$ | $1/2$ |

Результаты реализации совпадают с этими значениями. Дополнительно проверены несвязные графы и изолированные вершины. При проверке на фактических данных повторный экспорт дал тот же набор из 2 056 080 вершин и 5 311 246 рёбер.

## 7. Ограничения исследования

1. **Неполнота связей.** Закрытые профили, недоступные списки и незавершённый сбор изменяют наблюдаемую структуру. Отсутствие ребра в файле не означает отсутствия дружбы в VK.
2. **Граница двух кругов.** В этом наборе не наблюдаются связи между вершинами второго круга. Они могут создавать дополнительные пути и менять все три рейтинга.
3. **Смещение исходной выборки.** Сеть построена вокруг двух учебных групп и не является случайной выборкой пользователей VK. Исходные профили и профили с доступными списками могут выглядеть более центральными из-за способа сбора.
4. **Приближённые метрики.** Посредничество и близость рассчитаны по 2048 источникам. Небольшие различия оценок не гарантируют устойчивого порядка соседних мест; устойчивость отдельно не исследовалась.
5. **Временная изменчивость.** Списки получены в разные моменты, а дружеские связи могут изменяться. Набор представляет наблюдение за период сбора, а не синхронный снимок всей сети.
6. **Смысл показателей.** Центральности характеризуют положение профиля в собранном графе. Они не являются оценкой личных качеств человека или доказательством его социального влияния за пределами этого графа.

## 8. Выводы

В ходе работы реализован сбор данных о друзьях VK и построен граф из **2 056 080 профилей и 5 311 246 дружеских связей**. Для всех вершин получены оценки центральности по посредничеству, близости и собственному вектору, а для удобства сравнения выделены три топ-10.

Профиль `422397933` занимает первое место по посредничеству и близости, а профиль `823985240` - по собственному вектору. Различие лидеров и состава топов показывает, что разные определения центральности выявляют разные роли вершин в сети.

Задача сбора, построения графа и оценки центральностей выполнена **на доступной части данных**. Посредничество и близость получены приближённо; полный сбор связей и точный расчёт для всего графа не заявляются. Для повышения надёжности выводов следует дополнить списки первого круга, при необходимости собрать связи между вершинами второго круга и проверить устойчивость рейтингов на нескольких выборках.

## 9. Воспроизведение и материалы работы

Установка зависимостей:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Сбор с подготовленным `seeds.csv` и заданной переменной окружения `VK_TOKEN`:

```sh
.venv/bin/python collect_vk_graph.py
```

Расчёт с теми же параметрами выборки; вывод в отдельный файл сохраняет имеющийся результат:

```sh
.venv/bin/python analyze_graph.py --samples 2048 --random-seed 42 \
  --out data/centrality_reproduced.csv
```

Повторное формирование топов по сохранённым значениям:

```sh
.venv/bin/python analyze_graph.py --rank-only \
  --out data/centrality_exact.csv --top 10
```

Запуск тестов:

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Воспроизведение рейтингов предполагает те же файлы графа, параметры и совместимое окружение. Новая загрузка данных из VK может изменить граф и результат. Численный решатель собственного вектора также допускает небольшие различия округления между запусками.

Материалы, использованные при подготовке отчёта:

1. Судаков В. А. «Интеллектуальные системы и технологии (практика)», предоставленная презентация «ИСиТ пр.pdf», страницы 14-20.
2. [Сборщик данных](collect_vk_graph.py), [анализатор графа](analyze_graph.py) и [формирование рейтингов](reports.py) - реализованные алгоритмы и параметры обработки.
3. [Вершины](data/nodes.csv), [рёбра](data/edges.csv) и [кэш списков друзей](data/friends_cache.json) - исходные данные для исследования.
4. [Значения центральностей](data/centrality_exact.csv), [метаданные расчёта](data/centrality_exact.meta.json) и [три топ-10](data/centrality_exact_top10.md) - численные результаты.
