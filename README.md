# Граф друзей VK

Сбор друзей и друзей друзей исходных профилей, затем расчёт центральности для всех найденных вершин.

## Отчёт и сохранённые результаты

- [REPORT.md](REPORT.md) - отчёт по практической работе с методами, результатами и выводами.
- [RESULTS.xlsx](RESULTS.xlsx) - три топ-10 и показатели 33 исходных профилей на двух листах.

Выгрузка соответствует сохранённому расчёту с выборкой 2048 и `random_seed=42`. Посредничество и близость оценены приближённо; собственный вектор рассчитан численно без выборки. Файл расположен вне исключённой из Git папки `data/`.

## Установка

Нужны Python 3.10+ и `curl`. Сборщик использует стандартную библиотеку Python; для анализа нужны igraph и NumPy.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Все команды ниже выполняются из корня проекта. `data/`, список исходных профилей и токены исключены из Git.

## 1. Собрать данные

В `seeds.csv` укажите группу и профиль: числовой ID, короткое имя или ссылку. Один профиль может относиться к нескольким группам. Поддерживается и простой список профилей, по одному на строку.

```csv
group,profile
1,https://vk.ru/id123456
1,screen_name
2,987654
```

Задайте рабочий токен VK в переменной `VK_TOKEN`. Например, в zsh можно ввести его скрыто, без записи самого токена в историю:

```sh
read -rs 'VK_TOKEN?VK token: '; echo
export VK_TOKEN
.venv/bin/python collect_vk_graph.py
```

Короткие имена разрешаются через `users.get`. Далее `friends.get` получает списки друзей с пагинацией:

1. Друзья исходных профилей — первый круг.
2. Друзья первого круга — второй круг.

Опции:

```sh
# Постоянный интервал между запросами и лимит новых запрашиваемых профилей
.venv/bin/python collect_vk_graph.py --delay 2 --max-users 100

# Дополнительный проход: связи между профилями второго круга
.venv/bin/python collect_vk_graph.py --complete-boundary
```

Дополнительный проход не добавляет вершины третьего круга, но может потребовать очень много запросов. Без него связи между двумя вершинами второго круга известны лишь из уже сохранённых списков.

Каждый полностью полученный список сразу сохраняется в `data/friends_cache.json`. Уже сохранённые списки, включая пустые, повторно не запрашиваются. Формат кэша совместим с прежней версией. Для обновления конкретного списка удалите его запись из кэша.

Старые файлы состояния запросов, проверки профилей и кэши этапов анализа больше не используются. Существующие графы и результаты остаются совместимыми.

Предварительной проверки закрытости нет. Ошибки доступа к отдельному профилю записываются в `errors.csv`, сбор продолжается. Флуд, ограничения API, ошибки авторизации и сети останавливают сбор с сохранением частичного графа. `Ctrl+C` также сохраняет полученное. Автоматических повторов, бэкофа и восстановления сессии нет: новый запуск использует только успешные списки; неуспешные профили запрашиваются заново. Фиксированный интервал не гарантирует отсутствие ограничений со стороны VK.

Результат сбора:

| Файл | Содержимое |
| --- | --- |
| `friends_cache.json` | ID → полностью полученный список друзей |
| `nodes.csv` | ID, признак исходного профиля, группы и наличие списка друзей |
| `edges.csv` | Уникальные неориентированные связи без петель |
| `errors.csv` | Ошибки текущего запуска; depth 0 — исходные профили, 1 — первый круг, 2 — второй |

Код завершения: `0` — проход окончен или достигнут `--max-users`, `2` — сбор остановлен ошибкой, `130` — прерван вручную. Даже окончившийся проход не означает, что все списки доступны.

## 2. Проанализировать граф

```sh
.venv/bin/python analyze_graph.py

# Более крупная воспроизводимая выборка
.venv/bin/python analyze_graph.py --samples 2048 --random-seed 42

# Точный расчёт: на графе из миллионов вершин может занять очень много времени
.venv/bin/python analyze_graph.py --exact

# Только сформировать топы из готового результата
.venv/bin/python analyze_graph.py --rank-only --out data/centrality.csv --top 10
```

По умолчанию используется 128 источников для приближённого посредничества и до 128 опорных вершин в каждой компоненте для близости. Выборка определяет источники обходов, а показатели записываются **для всех вершин**. Вычисления выполняет нативный backend igraph. Прогресс показывает этапы расчёта; возобновления прерванных вычислений нет.

| Показатель | Как считается и что означает |
| --- | --- |
| Посредничество (`betweenness`) | Доля кратчайших путей через вершину; высокое значение у связующих узлов. Нормировка: `2 / ((n−1)(n−2))`. При выборке вклады источников умножаются на `n/k`. |
| Близость (`closeness`) | Обратное среднее расстояние до вершин своей компоненты с поправкой Wasserman–Faust `(c−1)/(n−1)`. В выборочном режиме расстояния оцениваются по случайным опорным вершинам. Изолированная вершина получает 0. |
| Собственный вектор (`eigenvector`) | Высокое значение у вершины, связанной с другими важными вершинами. Численный расчёт без выборки, L2-нормировка отдельно по компонентам; изолированная вершина получает 1. Между разными компонентами значения не следует сравнивать. |

Здесь `n` — число всех вершин, `c` — размер компоненты, `k` — число источников. Увеличение выборки помогает оценить устойчивость рейтинга; доверительные интервалы не рассчитываются. `--exact` использует все источники для посредничества и близости; собственный вектор всегда рассчитывается численно.

Результаты по умолчанию:

- `data/centrality.csv` — все ID и три показателя;
- `data/centrality.meta.json` — фактические методы, параметры и сведения о входном графе;
- `data/centrality_top10.md` — три топа со ссылками на VK;
- `data/centrality_top10_<показатель>.csv` — каждый топ отдельно.

`--top` меняет размер топа. При равенстве значений первым идёт меньший числовой ID. Метод определяется метаданными, а не именем файла: старый `centrality_exact.csv` мог быть рассчитан с выборкой. Для него используйте `--rank-only --out data/centrality_exact.csv`.

Анализ можно запускать на частично собранных данных. Все показатели описывают наблюдаемый граф: закрытые профили, недополученные списки и отсутствующие связи могут менять рейтинг. После нового сбора пересчитайте показатели. Не запускайте сбор и анализ одновременно для одной папки данных.

## Структура

- `collect_vk_graph.py` — VK API, кэш списков и экспорт графа.
- `analyze_graph.py` — загрузка графа и три метрики.
- `reports.py` — топы из CSV, без загрузки полного результата в память.
- `tests/` — проверка сбора, расчётов и рейтингов без запросов к VK.

```sh
.venv/bin/python -m unittest discover -s tests -v
```
